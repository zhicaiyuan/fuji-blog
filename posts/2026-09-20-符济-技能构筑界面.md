# 《符济》开发手记 #03：技能构筑页先立住「能学、能装」

你好，我是谈韦呓。画符识别能认出笔画之后，下一步是让玩家把符装进自己的构筑。这篇写技能页面这一版做了什么、刻意没做什么。

仓库：https://github.com/zhicaiyuan/Rune-of-Succor  
提交：`2a8e1a3`  
接入说明：`fuji/Docs/SkillTreeIntegration.zh-CN.md`

## 这一版要解决的问题

《符济》的战斗设想是：画符 → 识符 → 放技能。中间缺一层「我学过什么、装备了什么」。如果把学习规则散落在一堆 Widget 蓝图里，后面一改点数、前置、禁术就会炸。

所以这版把责任拆开：

- **成长状态唯一来源**：`UFujiSkillSubsystem`（Game Instance Subsystem）
- **界面只负责呈现与点选**：`UFujiSkillTreeWidget` + `WBP_技能界面`
- **战斗效果先不接**：数值和描述可读，36 个战斗效果留到后面

## 怎么打开

进第三人称关卡后按 **K** 打开技能页；再按 K、Esc 或点「返回」关闭。单人局里打开时会暂停；画符界面占着鼠标时，不会叠开技能菜单。

PlayerController 只加了独立的 K 输入和 `ToggleSkillMenu`，尽量不动原有角色 / 画符蓝图连线。

## 页面里有什么

复用 `/Game/UI/技能界面/WBP_技能界面` 的背景与布局骨架，运行时由原生类填内容：

- 三系（火 / 水 / 木）共 **18 主动 + 9 被动 + 3 精通**
- 另有 **6 个混系禁术**，独立页签查看
- 顶栏点数、右侧详情、朱砂边（可学）/ 青色状态（已学）
- 未达条件的节点仍可选中，右侧逐条列前置、投入门槛、点数、剧情条件；只有「修习」按钮禁用

学习与装备分开：被动最多 2 级；5 个主动符位，最多装备 1 个禁术。精通要本系投入 10 点、4 修习点及定道资格；精通费用不计入本系投入，同时只保留一个精通。

## 子系统管什么

`UFujiSkillSubsystem` 持有目录与存档态，界面所有修改都走它校验：

| 能力 | 用途 |
|------|------|
| `TryLearn` / `TryEquip` / `TryUnequip` | 学习与符位 |
| `GrantPoints` / `DiscoverSkill` / `SetMasteryUnlocked` | 剧情发放 |
| `OnBuildChanged` | HUD 刷新 |
| `SaveToSlot` / `LoadFromSlot` | 自动存读档 |

新档默认 24 修习点（`DefaultGame.ini` 可改），成功变更后自动写 `FujiSkillProgress_v1`。读档会校验版本、点数、等级、前置可达性、符位和精通；坏档不会静默覆盖。

## 和画符怎么衔接（还没焊死）

详情区已经能预览印头与符身轨迹：印头用鼠标选，旁边画横 / 竖 / 叉 / 圆 / 闪电 / 螺旋。被动和精通标明「无需画符」。

战斗侧约定是：

1. 保留完整符形模板库做识别；
2. 识别出结果后，再查 `GetLearnedRank` / `IsSkillEquipped`；
3. **不要**把识别模板库缩成当前装备列表，否则没装备的符形可能被误判成别的技能。

也就是说：识别管「画的是什么」，技能页管「你有没有资格放」。两层还没在战斗蓝图里焊死，但这是接口边界。

## 验证

自动化测试组名 `Fuji.Skills`：学习 / 装备、禁术 / 精通、存档校验、蓝图按钮回调。可加 `-FujiSkillScreenshots` 出界面截图。接入前备份在 `Saved/SkillUIIntegration/Backup`，不依赖 Git。

## 小结

这版技能页的目标不是「技能系统做完」，而是：

> 玩家能打开一页纸，看清三系与禁术，花点数学习，装进符位，关界面后进度还在。

画符识别提供字形，技能构筑提供资格与装备——下一步才是把识别结果接到具体元素技能 ID 和战斗效果上。

——谈韦呓
